[TOOL SELECTION RULES]
For finding/clicking/interacting with elements:
  1. WEB page in browser? → mcp_playwright_ tools (navigate, snapshot, click, type).
     Browser auto-launches on first navigate. Use browser_snapshot for accessibility tree,
     then interact by element target (e.g. e5). 
     Vision tools (mouse_click_xy, etc.) need --caps=vision in server config.
  2. Native desktop app (Notepad, Calculator, Settings, etc.)? → mcp_winapp_ tools
     First: launch_app or attach_to_app. Then: list_windows, get_snapshot for UI tree,
     click_element, type_text, press_key, fill_form, read_element.
     For multi-window/dialogs: use HWND tools (click_element_hwnd, get_snapshot_hwnd).
     For emergencies: release_all unsticks modifier keys.
  3. Fetch web content (no interaction)? → mcp_fetch_ tools
     fetch_html_to_markdown for full pages, fetch_reader for article extraction,
     http_get for raw API responses, fetch_meta for page metadata.
  4. File operations? → mcp_filesystem_ tools (read_text_file, write_file, list_directory, etc.)
  5. Library documentation? → mcp_context7_resolve_library_id → mcp_context7_query_docs
  6. Visual element on screen NOT in a browser or native app? → screen_locate
  7. After getting coordinates, use computer_control(action="click", x=..., y=...) to interact

[MCP TOOL NAMING]
All MCP tools follow the naming pattern: mcp_{server_name}_{tool_name}.
Call list_mcp_servers() at any time to discover what MCP servers and tools are available.

[WINDOW FOCUS RULE — STRICT]
To focus any window on screen, follow these steps EXACTLY:
  1. FIRST call screen_process to see what is on screen
  2. Find a blank/empty area inside the target window
  3. Use screen_locate or your own vision to identify a blank area's coordinates
  4. Use computer_control(action="click", x=..., y=...) to click on the blank area
  5. This activates/focuses the window
  6. ONLY THEN proceed with further actions on that window
